# QA 체크리스트

> Lv3 평가 루브릭(안내문) 4개 항목 기반. 8/1 기능 동결 후 전 항목 통과가 목표.

## 1. 첫 진입 이해 — "무엇을 하는 서비스인지, 다음에 뭘 눌러야 하는지"

- [ ] 입장(프로필 선택) → 책방 첫 화면만 보고 서비스 성격이 전달되는가 (시드 데이터 + 한 줄 설명)
- [ ] 빈 책방일 때 온보딩 문구 + 다음 행동(책 추가) 버튼이 보이는가
- [ ] 책 상세에서 "코멘트를 남긴다"는 다음 행동이 명확한가 (답글 진입점 포함)
- [ ] 문집 내보내기 진입점이 자연스럽게 노출되는가 (책방에서 책 선택 → 내보내기)

## 2. 주문 상태 — "사용자 입장에서 알아볼 수 있게"

- [ ] 상태가 코드(RECEIVED)가 아니라 사용자 말("접수됐어요")로 표시되는가
- [ ] 지금 어느 단계이고 다음이 무엇인지 스텝 표시로 보이는가 (8단계는 접수·제작·배송·완료 그룹으로)
- [ ] 주문일과 단계별 진행 날짜가 마이페이지·관리자에서 보이는가
- [ ] 배송 완료 후 주문자만 구매 확정을 누를 수 있는가
- [ ] 운영자가 단계를 진행하면 마이페이지 주문 화면에 반영되는가

## 3. 비정상 경로 — "빈 목록·로딩·실패·입력 실수에서 화면이 무엇을 말해주는가"

- [ ] 목록 로딩 중: 스켈레톤/로딩 표시
- [ ] 목록 비어 있음: 빈 상태 안내 + 다음 행동
- [ ] API 실패: 에러 메시지 + 재시도 수단
- [ ] 입력 실수: 필드별 검증 메시지 (무엇이 왜 잘못됐는지)
- [ ] 문집 내보내기: 코멘트가 없는 책 선택 시 안내
- [ ] 답글이 달린 코멘트를 삭제하면 스레드가 끊기지 않는가 ('삭제된 코멘트' 표시, 답글 보존)

## 4. 반응형

- [ ] 모바일 폭(375px)에서 책방·책 상세·코멘트 작성이 자연스러운가
- [ ] 코멘트 작성 폼이 모바일에서 한 손 조작 가능한가 (터치 타겟 크기)
- [ ] 데스크톱에서 문집 내보내기·admin 테이블이 제 폭을 쓰는가

## 제출 요건 (안내문 체크박스)

- [ ] `docker-compose up` 1회로 실행됨
- [ ] 포트를 환경변수/compose 수정으로 변경 가능
- [ ] 실행 직후 로그인 없이 더미 데이터로 바로 확인 가능
- [ ] README만 보고 실행 가능 (다른 폴더 클린 클론으로 검증)
- [ ] 레포 Public
- [ ] .env는 .gitignore, 시크릿 커밋 없음 (git log 확인)

## Lv2 로직 검증

- [ ] 8단계 순방향 전이 정상 (접수→확인→제작→제작완료→배송시작→배송중→배송완료→구매확정)
- [ ] 역행·건너뛰기 전이 서버 거부
- [ ] 구매 확정은 주문자(USER)만 가능 — 관리자·타 멤버 시도 거부
- [ ] 전이 이력이 단계별 날짜와 함께 기록되고 조회되는가
- [ ] 코멘트 수정 시 updatedAt 갱신, 삭제 시 deletedAt 마킹(소프트 딜리트) 확인
- [ ] CSV 다운로드 내용이 화면과 일치하는가
